# Multi-circuit extension (Build 2C requirements, preserving Build 3B)

The recovered published source was Build 3B. This change preserves both vehicles and the later engineering systems.

`lib/sim/track.ts` defines versioned CircuitDefinition records and pure makeTrack(definition). Units: coordinates, widths and station in meters; time seconds; speed m/s; curvature 1/m; grade rise/path distance (sin slope). World axes: x horizontal, y up, z reflected source northing. No geographic precision is claimed by the approximate circuit locator.

makeTrack derives finite cyclic distance, curvature and grade. `trajectory.makeCorridor(track)` derives heading radians and left/right boundary coordinates; 1.2m clearance is reserved. Schema metadata includes configuration/version, provenance, sectors, start/finish, geographic locator and explicit null unsupported banking, pit and kerb data. Physics has no Three.js/Cesium dependency.

Compatibility adapter: each UI or worker realm has one active track. selectCircuit atomically updates track and corridor; worker jobs are synchronous and select their circuit on every message. Each job carries circuitId, each result carries circuitId/trackVersion, and cache keys include track version. Future parallel jobs must use separate workers or pass a track context explicitly; do not interleave asynchronous solver jobs in one realm. Saved results are independently validated against their own circuit and do not mutate the active track. Legacy records default to Suzuka. Switching clears results and racing lines, preserves setups and uses circuit-specific custom-line storage.

F2004 optimization runs the existing bounded, vehicle-aware lap-time search on each circuit. Shared-line comparisons intentionally optimize for the baseline and freeze the path; independent mode optimizes each setup. SF-26 retains centerline/custom-line simulation; optimization remains unsupported, as in the recovered build.

Future Cesium adapter: discover geographic circuit -> obtain licensed data -> project WGS84/ECEF samples to a documented local metric frame -> populate CircuitDefinition coordinates/widths/elevation and source/license/accuracy metadata -> validate closed geometry -> register version. Preserve a reversible origin/frame transform for geographic overlays. Locator coordinates currently are only discovery hints, not a valid transformation for local samples. Terrain heights must be pinned and bundled with provenance, not streamed during physics. Surveyed elevation, banking and official timing data need explicit schema extensions before use; do not interpret null as measured zero. The current core runs fully offline after loading and needs no Cesium package or connection.

Verification: TypeScript, retained numerical regressions, new verify-circuits suite and production worker regression. Browser/WebGL QA unavailable in this environment; visual selection, camera and road appearance require manual confirmation after publication. Test script `node tests/run-typescript.mjs verify-circuits` verifies lengths, finite geometry, bounded optimized paths, completed laps, setup/power sensitivity, extreme setup bounds, both vehicle simulations, immutable setups, mixed-circuit history and CSV identity. Comparisons across circuits show descriptive metrics; detailed deltas require matching selected circuit. No cross-circuit raw-time superiority claim.

Spa is enabled in the final release. Its map-derived outline uses the same transform and length normalization; sparse operator station/altitude facts drive an explicitly approximate vertical reconstruction with uncertain origin alignment (see public/data/CIRCUITS.md). No downloaded map imagery is used. Monza remains flat. Cross-circuit history includes identical-setup filtering, average/top speed, braking/lateral g, three time-weighted speed bands and a percent time delta against the first stored matching-model run on each circuit. This baseline can include line differences and is labeled accordingly. Full speed/force/sector traces and saved A/B comparison require the selected circuit to match both results. Storage remains quota-limited with explicit export/retry and no automatic eviction.

CPU scene regression found the reused wide runoff strip overlapping Spa La Source. New circuits now omit unsupported runoff strips, kerbs, barriers, fences and Suzuka-specific buildings; the continuous asphalt, boundary markings and terrain remain. Three.js raycasts verify road support and no centerline obstacles, with no WebGL dependency.
